# APEX · Wi-Fi Observatory

[Открыть dashboard](apex-dashboard.html) · [Архитектурное видение](../VISION_MODERN_AIRCRACK.ru.md)

`apex-dashboard.html` — автономный интерактивный эскиз информационной архитектуры
Wi-Fi-модуля aircrack-rs для EASM. Откройте файл в браузере напрямую: сборка,
сервер, сеть и внешние зависимости не требуются. CSS и JavaScript встроены;
шрифты системные. Начальная тема — тёмная.

## Что работает

- Переключение таблицы AP / клиентов: 6 вымышленных AP и 4 клиента.
- Поиск по SSID/MAC/защите (для клиентов также по последнему AP) и фильтр диапазона.
- Выбор имени в таблице открывает evidence inspector, сохраняя фокус на кнопке.
- RSSI в dBm с полосками сигнала; неизвестное значение показано как `?`.
- Evidence badges HS / FT / PMKID с явными границами интерпретации.
- Переключение dark/light без записи предпочтения и без сетевых запросов.
- Экспорт полного **синтетического** набора в JSON, независимо от фильтров.
- Адаптивная компоновка: sidebar на desktop, перенос панелей на узком экране,
  горизонтальная прокрутка широкой таблицы. Клавиатура: Tab / Shift+Tab / Enter;
  видимый focus ring, подписи контролов, live-статус результата поиска.

Навигация слева — статическая карта будущих разделов, а не ссылки/кнопки.
Счётчики, карта каналов, coverage, время и бюджет фиксированы для демо и не
пересчитываются при фильтрации. Набор объединяет несколько окон наблюдения;
канал 6 в строке источника описывает последнее окно. AP по каналу — не загрузка
эфира. Backend Shapoclyack и radio API не подключены; capture не импортируется.

## Палитра

CSS использует семантические переменные `--apex-*`. Заданная тёмная палитра:

| Роль | Цвет |
| --- | --- |
| Canvas | `#0b0f14` |
| Card | `#121826` |
| Border | `#1f2633` |
| Accent | `#4f8cff` |
| Success | `#3dd68c` |
| Warning | `#f5a524` |
| Danger | `#ff5d5d` |
| Muted | `#8a94a6` |

Light-тема переопределяет те же переменные; у контролов отдельная контрастная
граница. Статусы различаются словами и цветом. Это палитра данного концепта,
а не обновление vendored APEX-токенов Rust/Android или свидетельство прохождения
их acceptance gates.

## Границы и проверка

Все MAC — локально администрируемые вымышленные адреса `02:00:00:…`, имена,
evidence ID и наблюдения также синтетические. JSON помечен `mockup: true` и
`apex-demo-only/v1`; он **не является контрактом** CLI или Shapoclyack ingest.
HS/PMKID не подтверждают MIC, пароль или взлом, FT не подтверждает завершённый
роуминг. Открытая сеть сама по себе не доказывает нарушение политики организации.

Для ручной проверки: открыть файл, сменить тему, выбрать AP и клиента, ввести
`Lab`, затем строку без совпадений, проверить диапазоны и очистку поиска.
Проверить экран около 390px и desktop, пройти контролы клавиатурой и скачать
JSON. В DevTools Network не должно быть внешних запросов. JavaScript необходим
для таблицы и действий; без него отображается соответствующее сообщение.

Макет не реализует нативные Android/macOS UI или TUI. Их целевой UX, ограничения
платформ и этапы приёмки описаны в архитектурном видении.
