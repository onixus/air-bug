# Диагностика пассивного обзора на macOS — 2026-10-27

## Итог

На проверенном Mac при подключённом Wi-Fi (`en0`, CoreWLAN mode 1, канал 44)
обычный Ethernet-захват работал, но Radiotap-захват не получал кадров. После
временной диссоциации (mode 0) прямой tcpdump получил **1202 пакета**, а CoreWLAN
успешно установил каналы **1 и 6** с подтверждением через `wlanChannel()`.

Проверка с диссоциацией прервала сетевое подключение пользователя. После теста
был восстановлен канал 44, питание Wi-Fi выключено/включено для автоподключения;
автоподключение оказалось не мгновенным. Последующая независимая проверка
подтвердила `power on`, `mode 1`, канал 44 и HTTPS-ответ 200. Дальнейшие
отключения и аппаратные переключения после сообщения пользователя не выполнялись.

Новый `survey` **отказывает до открытия BPF на подключённом Mac-адаптере**.
Программа не отключает сеть ради обзора. Для monitor-захвата нужен отдельный
неподключённый адаптер; универсальная поддержка всех Mac не заявляется.

## Среда и независимые проверки

- macOS 26.7.1, build 25G241, arm64.
- `/usr/sbin/tcpdump` 4.99.1, Apple version 158; libpcap 1.10.1.
- Все аппаратные захваты были пассивными, короткими, с ограниченным snapshot
  length; без injection, активного сканирования или изменения BPF permissions.
- Административный доступ подтверждал пользователь в системном диалоге macOS.
  Имена сетей, MAC-адреса и реальные пакеты в репозиторий не добавлены.

pipeline обновлённого CLI после восстановления связи повторно не запускался.

## Причины и изменения кода

### Завершение процесса

Authorization Services передал процессу заблокированную маску сигналов,
включавшую SIGINT, SIGTERM и SIGHUP. Установка обработчиков в CLI эту маску
не разблокировала; она наследовалась tcpdump через exec. Поэтому штатный stop
не срабатывал, а supervisor через две секунды применял SIGKILL.

CLI теперь разблокирует свои сигналы завершения после установки обработчиков.
Перед exec дочернего capture-процесса сбрасываются disposition и mask этих
сигналов. Сигнал отправляется системным вызовом только собственному unreaped
child. Регрессионный тест с заблокированным SIGINT воспроизвёл `ForcedTermination`
до исправления и проходит после него. У тестовых shell-процессов увеличен запас
на параллельный fork/exec в macOS; production duration limits не изменены.

### Приём кадров и каналы

Отсутствие кадров воспроизвелось в прямом tcpdump без фильтра и без нашего
декодера. Immediate mode не изменил результат. Во время этих запусков адаптер
оставался в station mode. После диссоциации пошли кадры и заработало tuning.
Это подтверждает необходимое условие на данной машине, но не устанавливает
внутреннюю причину поведения закрытого драйвера и не распространяется на все Mac.

[Контракт CoreWLAN](https://developer.apple.com/documentation/corewlan/cwinterface/setwlanchannel(_:))
не разрешает смену канала при ассоциации. Ранее helper пытался установить даже
тот же канал 44 с шириной 20 MHz вместо текущей ширины и при любой ошибке печатал
одну общую подсказку. Теперь:

- чтение состояния возвращает power/mode/current; неизвестное состояние не
  считается разрешением на monitor capture;
- `survey` проверяет состояние до запуска tcpdump и отказывает для station mode;
- удержание уже текущего канала не вызывает set и не меняет ширину;
- реальное переключение требует подтверждения канала обратным чтением;
- ошибка CoreWLAN содержит domain/code и состояние, без выдуманной причины;
- после отказа set восстановление сначала проверяет фактический канал и не
  вызывает лишний set, если исходный канал уже сохранён;
- survey с нулём пакетов завершается диагностической ошибкой, а не подтверждает
  работоспособность monitor mode наличием одного заголовка PCAP;
- production helper не содержит команды диссоциации, активного scan или смены
  питания. Временная диагностическая процедура не включена в продукт.

Исходные приватные результаты находятся вне репозитория в
`/private/tmp/air-survey-diagnosis/`; предыдущие неуспешные попытки — в
`/private/tmp/air-survey-hardware.PgNaKZ/`.

## Финальные офлайн-проверки

После исправлений: **81 Rust-тест прошёл**, rustfmt и строгий Clippy прошли,
release CLI и CoreWLAN helper собраны. Проверки включают наследуемый blocked
SIGINT, отказ preflight на station/unknown/power-off, обязательный readback и
отсутствие лишнего восстановления после отклонённого set. Старый тест blocked
SIGINT воспроизвёл ошибку до исправления. Отдельно проверен отказ нового release
CLI на реальном подключённом en0: файл захвата не создан, состояние осталось
mode 1 / канал 44. Дополнительного радио-захвата после восстановления связи нет.
